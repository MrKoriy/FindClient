# CRM рассылки

Панель учёта: что кому отправлено, кто ответил, что ещё не тронуто.

## Зачем отдельная база

CRM пишет в `crm.db`, а не в `scraper.db` бота. Бот при старте делает
автомиграции своей схемы; если бы CRM писала в ту же базу, ошибка в схеме
ломала бы бота. История переписки — данные, которые дороже любой выгрузки,
и терять их из-за чужой миграции не хочется.

Цели подтягиваются из таблицы `organizations` бота: это компании с карт.
Рабочими целями становятся те, у кого **нет сайта** — им и продаём сайт.
Компании с сайтом попадают как `skip`, чтобы не выпадать из виду.

## Установка

```bash
cd /opt/2gi_scraper && bash deploy/install_crm.sh
```

Скрипт идемпотентен: повторный запуск не меняет пароль и не трогает базу.
Панель поднимается на `https://94-103-1-126.sslip.io:9444/` — sslip.io даёт
имя для голого IP. Certbot на сервере сломан, поэтому nginx терминирует TLS
сертификатом по умолчанию на отдельном порту 9444.

**Порт, а не имя.** Голое `94-103-1-126.sslip.io` (порт 443) занято
`shift-plus.conf`, и это не пустой конфиг: он проксирует `/vless-xhttp`
на Xray и `/` на `127.0.0.1:8080`. Первая версия панели села на то же имя,
nginx выбрал её первой (файлы подключаются по алфавиту), и VLESS-эндпоинт
начал отдавать 401 вместо прокси. Установщик проверяет **порт** на
конфликт и падает, если он занят.

## Запуск руками

```bash
cd /opt/2gi_scraper
set -a; source crm.env; set +a
venv/bin/python -m crm.app      # панель
venv/bin/python -m crm.sender   # воркер отправки
```

## Что чем управляется

| Файл | Зачем |
|---|---|
| `crm/db.py` | схема и запросы: цели, шаблоны, журнал, группы, настройки |
| `crm/templates.py` | шаблоны, подстановка переменных, проверка на спам-признаки |
| `crm/offer.py` | генератор офферов, стратегии, классификатор качества AI + Jev Judge |
| `crm/app.py` | HTTP-панель и JSON-API |
| `crm/sender.py` | воркер отправки с лимитами и паузами |
| `crm/static/index.html` | сам интерфейс, один файл, без внешних зависимостей |

## Лимиты

Отправка по умолчанию **выключена** и в **холостом режиме**. Это не
перестраховка: воркер с включённой отправкой начинает расходовать запас
доверия аккаунта сразу, а откатить это нельзя.

Значения по умолчанию: 10 сообщений в день, пауза 90–240 секунд, длинная
пауза 20 минут после каждых 8 сообщений, рабочие часы 10:00–20:00.

Почему именно так: Телеграм считает не только объём, но и **скорость**.
Растянутые 30 сообщений на 6 часов ограничение не ловят, те же 30 за полтора
часа ловят почти всегда. Дневной лимит без пауз — половина защиты; вторая
половина — это паузы.

## Проверка шаблона

`crm/templates.py:check()` возвращает список замечаний. Он ловит:

- больше 50 слов;
- длинное тире;
- больше одного вопроса;
- прайс в первом сообщении;
- неизвестные переменные;
- падеж: «в {city}» даст «в Санкт-Петербург», потому что подставляется
  именительный падеж;
- мусор при пустых данных: «Нашёл вас на картах: .»

Отдельно: рейтинг ниже 4,0 в текст не попадает. «1,0 и 2 отзыва» в первом
сообщении работает против нас — это тычок в слабое место, а не комплимент.
