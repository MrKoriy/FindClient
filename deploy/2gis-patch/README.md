# 2GIS на сервере, который не видит 2gis.ru

Патч для `/opt/2gi_scraper` на `94.103.1.126`. База — коммит `5940bc4`.

## Проблема

С этого сервера `2gis.ru` и `catalog.api.2gis.ru` недоступны **полностью**:
адреса `91.236.48.0/22`, TCP 443 не открывается, ping 100 % потерь.
Провайдер/2GIS режут по IP. При этом 2GIS жив: страница нормально отдаётся
через любой сторонний путь.

Раньше это лечили только прокси, но рабочего прокси нет:
- `127.0.0.1:3128` (локальный релей → SOCKS5 `151.241.161.68`) отдаёт 403
  от своего upstream — 2gis.ru не в белом списке;
- внешний `socks5h://…@23.229.17.54:9580` мёртв;
- Xray на сервере — это VLESS-**сервер** с outbound `freedom`, то есть наружу
  ходит тем же заблокированным маршрутом;
- прогон 5 031 бесплатного прокси (RU + общие списки) по `2gis.ru` — **0 попаданий**.

## Решение: три источника, два обхода

| Что нужно | Откуда берётся |
|---|---|
| `webApiKey` | страница `2gis.ru/moscow` — напрямую, иначе через публичный читатель `r.jina.ai` |
| соль подписи | бандл `app.<hash>.js` — **напрямую** с `d-assets.2gis.ru` (другой адрес, не заблокирован) |
| сам API | `catalog.api.2gis.ru` — напрямую, иначе на edge DDoS-Guard |

Ключевые находки:

1. **`d-assets.2gis.ru` → `95.129.232.210` (`ddos-guard.2gis.ru`) и доступен
   напрямую.** Это тот же edge DDoS-Guard, что обслуживает и API: если
   подключиться к `95.129.232.210`, сохранив SNI `catalog.api.2gis.ru`,
   API отвечает штатно. Адрес edge резолвится в рантайме, а не хардкодится.
2. **Читатель `r.jina.ai` отдаёт сырую страницу** (715 007 байт, ключ внутри)
   при `X-Return-Format: html`. Нужен только для ключа, ~раз в 6 часов.
3. **Читатель отвечает 403 на браузерный User-Agent** и 200 на небраузерный.
   Это не TLS-фингерпринт (curl_cffi с `impersonate="chrome"` тоже получает
   403), а именно UA: поэтому в коде для читателя стоит `curl/8.5.0`.
   Проверено перебором: Chrome UA → 403, curl UA → 200, без UA → 200.
4. Если 2gis.ru когда-нибудь станет доступен напрямую, оба обхода молча
   выключаются: сначала всегда пробуется прямой путь, обход — только после него.

## Что изменено

`api/twogis_api.py`
- `_EdgeResolver` — подменяет адрес только для `catalog.api.2gis.ru`, оставляя
  настоящий SNI/Host. Адрес edge кэшируется на час.
- `TwoGISApi._fetch()` — сначала прямой путь, при провале edge. Как только
  прямой провалился, процесс больше не платит за него таймаут.
- `_page()` — прямое чтение, затем читатель с 3 попытками и нарастающей паузой.
- `_fetch_creds()` — страница + бандл (бандл тянется напрямую).
- `_credentials()` — не теряет рабочий ключ: свежий из памяти → диск →
  `.env` → сеть. Если обновление не удалось, работает на прежнем ключе.
  Ключ сохраняется в `twogis_creds.json` рядом с базой, поэтому рестарт бота
  не зависит от читателя.
- Появился `close()` и приём `proxy` (раньше прокси до 2GIS не доходил).

`services/scrape_service.py`
- `proxy` передаётся в `TwoGISApi`;
- `await api.close()` в `finally` — иначе сессия для edge утекала бы на каждый запрос.

## Аварийный выход

Если ни страница, ни читатель не отвечают, ключ можно вписать руками в `.env`:

```
TWOGIS_WEB_KEY=<webApiKey>
TWOGIS_SIGN_SALT=<соль>
```

Читаются как последний резерв — после дискового кэша.
